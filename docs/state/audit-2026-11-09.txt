## Defects found and fixed

1. tools/decky-oxp3-status/build.sh --help was broken.
   It ran `cd "$here"` and then `sed ... "$0"`; with a relative invocation $0 no
   longer resolved, so it printed `sed: can't read ...`, no help, and still exited
   0 (the pipeline exit status hid it). Fix: read "$here/${0##*/}" and stop the
   header range at line 11 (it also printed `set -eu`). Regression test:
   tests/unit/test_cli_contracts.py::DeckyBuildHelpTest.

2. tools/oxp3-hw-install.sh rejected an unknown option with exit 1, while its own
   header (and docs) say 2 = usage, 1 = runtime error. Fix: print and exit 2.
   Regression test: InstallerUsageTest.

3. tools/oxp3-verify.sh ensure_status_json() had two wrong-verdict bugs:
     a) the cache guard `[ "$STATUS_READY" -eq 1 ] && { [ -n "$STATUS_JSON" ]; return 0; }`
        returns 0 even when STATUS_JSON is empty, so every later caller believed
        the report was available;
     b) it accepted only exit 0. oxp3-status exits 1 when any indicator is "fail",
        which is a valid report, so the JSON was thrown away exactly when it
        mattered and decky.status/gfx.*/pwr.rapl degraded to SKIP/UNKNOWN.
   Demonstrated in a temp copy with a status backend forced to overall=fail:
     before: pwr.rapl skip "status backend unavailable"; gfx.mesa unknown
             "indicator missing"; decky.status unknown "no overall field"
     after : pwr.rapl pass; gfx.mesa pass; decky.status fail overall=fail
   Fix: explicit cache branch returning 1 on empty, and accept rc 0|1 (still
   rejects 2 = --strict and 3 = backend start failure). Live run is otherwise
   unchanged (same 72 checks / 41 pass / 4 fail / 27 skip). Regression tests:
   VerifyStatusConsumerTest (behavioural, runs the real function body against
   stubbed outputs).

4. Stale documentation numbers corrected (behaviour had moved on):
     docs/hw/components.yaml  fingerprint expect "Ran 85 tests" -> 172, then
                              tools/gen-docs.py --write regenerated
                              docs/INSTALL-HW.md (only that row changed)

                              (it takes ~15 s, outside the documented <5 s tier)
